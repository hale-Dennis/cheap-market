## Story
**As a** Buyer,
**I want** to add items to a shopping cart and adjust quantities,
**so that** I can prepare my order before purchasing.

## Acceptance Criteria
1. The "Add to Cart" button on a product detail page adds the selected item to the user's cart.
2. The buyer can view their cart at any time, seeing a list of all items, their quantities, and individual/total prices.
3. From the cart view, the buyer can change the quantity of any item.
4. From the cart view, the buyer can remove an item completely.
5. The cart's contents persist for a logged-in user, even if they leave the site and return later.

- Max quantity per item 99.
- Prevent adding product with `listingStatus != ACTIVE`.
- Cart total recalculated on each update.
- Attempt to add inactive product returns HTTP 422 with error code `INACTIVE_PRODUCT`.

## Dev Agent Record

### Implementation Notes
- **Backend** (the cart entity and `GET`/`POST`/`DELETE /cart/items/{id}` already existed):
  - Added `DELETE /cart` (clear) for the `clearCart` action.
  - Adding a product that isn't for sale (inactive, sold out, **or from a suspended farmer**) returns **422 with `"code": "INACTIVE_PRODUCT"`**. API errors now carry an optional `code` field for cases clients handle specially.
  - The cart shows **current prices**; items no longer for sale are returned with `available: false`, excluded from `subtotalCents`, and can only be removed. Each item also has unit, farmer name and line total. The stored price is refreshed whenever the quantity changes.
  - Items keep the order they were added (`addedAt`; rows from before this change sort first), and items, products and farmers load in one query.
  - **No CartService tests existed**; added unit, controller and real-Postgres persistence tests (the cart survives a fresh session, keeps order, deletes removed items).
- **Frontend:**
  - `/cart` (buyer-only; signed-out visitors go to sign-in and back): rows with photo, name, unit price and farmer, − / number / + stepper (1–99), line total and Remove; order summary; "Empty cart" with confirmation; `EmptyCart` state. Unavailable items are flagged and their totals struck through.
  - The cart "context" is the shared SWR cache plus `useCartActions()` (`addItem`, `updateQuantity`, `removeItem`, `clearCart`), used by the cart page, the header and Add to Cart. Changes show instantly and roll back with a message if the API refuses. **Writes are sent one at a time**, so fast clicks can't reach the server out of order. This lives in `apps/web/hooks/useCart.ts` rather than a `packages/ui` package, which doesn't exist.
  - **Add to Cart now adds to the quantity already in the cart** (capped at 99) and its toast links to the cart. The header cart badge links to `/cart` and appears on buyer pages too.
  - Persistence is the backend cart (AC5), so the cart follows the buyer across devices; a guest `localStorage` cart remains a future enhancement as the story notes.
- Checkout from the cart is Story 3.2.
- **Fixed while testing:** a nameless image link in each row (axe), rows overflowing 360 px phones, and the summary counting unavailable items.
