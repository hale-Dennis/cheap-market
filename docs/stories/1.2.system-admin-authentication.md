### Business Context
Secure admin authentication is the cornerstone for managing users and administrative features defined in Epic 1. It ensures only authorized administrators can perform tasks such as creating farmer accounts, viewing sensitive data, and approving future catalog or order actions.

### Dependencies
- Requires Story 1.1 (Project Scaffolding & Initial Deployment) to be completed and merged to `main`.

## Story
**As a** System Admin,
**I want** a secure login system,
**so that** I can access the administrative functions of the platform.

## Acceptance Criteria
1. A `/login` page exists on the frontend application.
2. An admin can log in using predefined credentials (to be stored securely as environment variables for the MVP).
3. Upon successful login, the admin is redirected to a private Admin Dashboard page.
4. The system securely manages the admin's session.
5. Any attempt to access admin pages without being authenticated redirects the user to the login page.

## Dev Agent Record

### Implementation Notes
- **Admin credentials (AC2):** `ADMIN_USERNAME` / `ADMIN_PASSWORD` seed an `ADMIN` user at startup (`AdminUserInitializer`); `/auth/login` authenticates against that user via Spring Security. Same login endpoint serves buyers (Story 1.5).
- **JWT:** access tokens now carry a `role` claim so the frontend can authorise without calling the API. Lifetime is 1 hour (`application.security.jwt.expiration`).
- **Session (AC4):** the browser never sees the token. `POST /api/auth/login` (Next.js API route) calls the backend and stores the access token in an `HttpOnly; SameSite=Lax` cookie (`Secure` in production). `POST /api/auth/logout` clears it. The refresh token is not stored yet; users sign in again after 1 hour.
- **Route protection (AC5):** `apps/web/middleware.ts` verifies the cookie's JWT signature/expiry with `JWT_SECRET` and requires `role=ADMIN` for `/admin/**`, redirecting to `/login?next=…` otherwise. `/admin` also re-checks in `getServerSideProps`.
- **Backend hardening:** `/api/v1/admin/**` now requires `ROLE_ADMIN` at the URL level (previously `PUT`/`DELETE /admin/farmers/{id}` had no role check). Malformed/expired tokens now yield 401 instead of an unhandled filter exception. The 401/403 JSON handlers now use Spring's `ObjectMapper` (the bare one could not serialise `Instant` timestamps).
- **Re-login fix:** `RefreshTokenService` now rotates the user's existing refresh-token row; the old delete-then-insert was flushed insert-first by Hibernate, so any user's second login failed with a unique-constraint error (found running the stack in Docker).
- **Local stack:** `docker compose up --build` runs Postgres + API + web; see README.
- **Deployment:** the web app must run as a Node service on Render (not a static site) for middleware and API routes; `render.yaml` updated. Web needs `API_BASE_URL` and the same `JWT_SECRET` as the API.
