## Story
**As a** Buyer,
**I want** to view a history of my past and current orders,
**so that** I can track their status.

## Acceptance Criteria
1. A logged-in buyer can access an "My Orders" page from their profile.
2. The page lists all their past and present orders, showing at least the order date, total price, and current status.
3. The current status can be one of: "Pending," "Ready for Pickup," "Out for Delivery," "Completed," or "Disputed.".

## Dev Agent Record

### Implementation Notes
- **`GET /orders`** (existed; extended): returns the signed-in buyer's own orders, **10 per page, newest first** (`createdAt` desc, then `id`, so the order is stable across pages). `page` (≥ 0) and `size` (1–50) are validated, and bad values return 400. Admins get 403. Each summary now also carries `orderNumber`, `fulfillmentType` and `itemCount`. `itemCount` is the total quantity, computed in the same query with a Hibernate `@Formula`, so there's no N+1.
- **My orders page (`/orders`):** buyer-only (signed-out visitors go to sign in and back). It's linked from the header for buyers, the buyer account header, and the profile page ("View my orders").
  - Each row shows the order number, date, item count, fulfillment, status badge and total, and links to the order.
  - Status badges: Pending (amber), Ready for Pickup (blue), Out for Delivery (orange), Completed (green), Disputed (red). All have AA contrast.
  - Empty state: an illustration and a "Browse produce" link.
- **Infinite scroll:** uses `useSWRInfinite` with an `IntersectionObserver` sentinel.
  - The next page is **prefetched** while the end of the list is still 600 px below the viewport, and a spinner shows while it loads.
  - A "Load more orders" button is also shown, for keyboard users and browsers without `IntersectionObserver`.
  - "That's all your orders." appears at the end.
- **Order detail (addition):** the story mentions a future detail page, but rows needed somewhere to go. `/orders/{id}` reuses the 3.3 confirmation view in a `detail` variant, which shows "← My orders" and "Order CM-…" instead of the thank-you message. The confirmation page now links to "View my orders".
- **Bug fixed (found on the real stack):** the catch-all exception handler turned client errors into **500**: a wrong HTTP method (e.g. `PUT` on a `PATCH` endpoint), a non-JSON content type, and an unknown path for a signed-in user. These now return **405** (with an `Allow` header), **415** and **404**.
- **E2E stub:** now exposes the real admin status endpoint, `PATCH /admin/orders/{id}/status`. The API docs had said `PUT /admin/orders/{id}`.
- **Test reliability:** axe scans in all E2E specs go through a shared `scanWcag()` that waits for animations (e.g. toasts) to finish first. A mid-animation toast had made the checkout scan flaky under load.
