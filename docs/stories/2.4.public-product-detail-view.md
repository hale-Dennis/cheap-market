## Story
**As a** Buyer,
**I want** to view the full details of a specific product,
**so that** I can make an informed purchasing decision.

## Acceptance Criteria
1. Clicking on a product in the catalog navigates the user to a unique detail page for that item.
2. The detail page displays all information: name, all photos, description, price, unit, and harvest date.
3. The page clearly displays the name of the farmer selling the produce and their current star rating.
4. An "Add to Cart" button is prominently displayed.

## Dev Agent Record

### Implementation Notes
- **Backend `GET /products/{id}`** (existed): now applies the catalog's visibility rules (active listing **and** non-suspended farmer, else 404), loads farmer and category in one query, adds the category name and the farmer's region and rating count, and is cacheable for 5 minutes (404s are not). A malformed id returns 400.
- **Rating:** the farmer's `averageRating`/`ratingCount` come with the product, so no separate `GET /ratings?farmerId=` call is needed. "No ratings yet" shows when the count is 0/null. (Nothing updates these aggregates until Story 3.5.)
- **Page `/products/[productId]`** is server-rendered (for search engines and link previews): gallery with previous/next, thumbnails and arrow keys, placeholder when there are no photos; name, category, price per unit, harvest date ("24 October 2026 (today)"), description, farmer card with stars; `<meta>` description/Open Graph tags and schema.org **Product JSON-LD** (price in GHS, images, rating when present). Unknown or unavailable products render a friendly 404 page.
- **Images:** for Cloudinary URLs the page requests resized, auto-format variants (`f_auto,q_auto,w_…`) with `srcset`; thumbnails lazy-load. This replaces Next's image optimiser, which isn't configured for Cloudinary/proxied sources.
- **Add to cart:** the backend cart already existed, so the button really adds (quantity 1–99, `POST /cart` sets that quantity). Visitors see "Sign in to add to cart" (returning to the product afterwards) plus a sign-up link; admins see that only buyers can buy. Signed-in buyers get a cart count in the header, shared via SWR, which updates after adding. The cart page itself is Story 3.1.
- **Responsive header:** the signed-in buyer header overflowed 320–390 px phones; it now wraps and shortens the cart label.
- API client functions: `services/productDetailService.ts` (server-side) and `services/cartService.ts`, matching the existing service layer.
