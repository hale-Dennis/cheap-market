## Story
**As a** System Admin,
**I want** to create and manage produce categories (e.g., "Vegetables," "Fruits," "Grains"),
**so that** produce listings can be properly organized for buyers.

## Acceptance Criteria
1. An authenticated admin can access a "Categories" management page from their dashboard.
2. The admin can add a new category by providing a name.
3. The admin can edit the name of an existing category.
4. The admin can delete a category.
5. The list of categories is persisted in the database.

## Dev Agent Record

### Implementation Notes
- **Backend** (entity, repository, endpoints and ADMIN security already existed): names are trimmed and internal whitespace collapsed; duplicates are rejected case-insensitively (409), including renames, while changing only the letter case of a category's own name is allowed. A duplicate inserted concurrently is caught at flush and reported as 409 instead of a generic 400 database error. The list is sorted by name (case-insensitive). Deleting a category used by products returns 409; unknown ids return 404.
- **Database:** the `categories` table (with a unique `name` column) is created by Hibernate (`ddl-auto: update`); there is no migration tool in the project yet. The DB-level unique constraint is case-sensitive; case-insensitive uniqueness is enforced by the service.
- **Frontend:** `/admin/categories` (linked from the dashboard and admin nav) with `CategoriesTable`, `CategoryFormDialog` (add/rename) and `DeleteCategoryDialog` (confirmation; keeps the API's reason visible, e.g. "in use"). Built on shadcn/ui-style `Dialog`/`AlertDialog` wrappers over Radix, so focus is trapped and Escape closes. Client-side validation: required, ≤ 50 characters. Empty state prompts adding categories.
- **Accessibility:** an axe-core scan (WCAG 2.1 A/AA) of the page and the open dialog runs in E2E. It caught that sonner's `richColors` success toast (green on pale green, ~4.3:1) fails AA contrast, so toasts now use the default dark-on-white style. Toasts moved to bottom-right so they don't cover the header.
- API client functions live in `services/categoryService.ts` rather than `lib/api/admin.ts`, matching the existing service layer.
