## Story
**As a** Buyer,
**I want** to view a public catalog of all available produce filtered by my region,
**so that** I can easily see what is available for purchase near me.

## Acceptance Criteria
1. A public `/products` page exists that is accessible without logging in.
2. The page displays all active produce listings in a grid or list format.
3. Each item in the catalog displays at least its name, price, and primary photo.
4. The catalog is automatically filtered to show only produce from farmers in the buyer's selected region.
5. The buyer can further filter the catalog by produce category.

## Dev Agent Record

### Implementation Notes
- **Bug fixed:** the public catalog (and product detail) responses always had `priceCents: null` — the mapper never converted the stored price. Cards now also carry harvest date, farmer name and category name.
- **Backend `GET /products`:** `region` is required and must be a valid region code (400 otherwise); optional `categoryId`; `page` ≥ 0 and `size` 1–100 (default 20) are validated like the farmer list. Only `ACTIVE` listings from `ACTIVE` (not suspended) farmers are returned, newest first in a fixed order. Farmer and category are fetched in the same query (no N+1). Responses carry `Cache-Control: public, max-age=300`, which the web proxy now passes through.
- **Categories for the filter:** the story pointed at `/admin/categories`, which buyers can't call; a public, cacheable `GET /categories` was added instead.
- **Frontend `/products`** (public; linked from the home page): grid of `ProductCard`s (photo with lazy loading and a placeholder when there is none, name, price with unit, category, "Harvested N days ago" and farmer), category filter, pagination (only shown when there is more than one page), and empty states for an empty region or an empty category. Category and page live in the URL (`?category=…&page=…`).
- **Region:** stored in a `cm_region` cookie. First-time visitors are asked to pick one; signed-in buyers without the cookie get their profile region automatically (read server-side), and saving a new region on the profile updates the cookie. Visitors can change region from the catalog.
- Cards link to `/products/{id}`, which Story 2.4 implements.
- API client functions live in `services/catalogService.ts` rather than `lib/api/public.ts`, matching the existing service layer.
- **Tests:** the region/category/status/suspended-farmer filtering and pagination are verified against real PostgreSQL (`ProductCatalogQueryTest`, uses the CI Postgres service). The farmer-list E2E page-overlap check was made robust to farmers being added concurrently by other specs.
