## Story
**As a** new user,
**I want** to sign up for a buyer account,
**so that** I can track my orders and save my delivery information.

## Acceptance Criteria
1. A public "Sign Up" page is available.
2. A user can register with their name, email, password, and home region.
3. Upon successful registration, the user is automatically logged in.
4. An authenticated buyer can view a basic profile page where they can manage their delivery details.

### Technical Constraints
- Passwords stored as BCrypt hashes; enforce minimum 8 chars.  
- JWT expiry 1 hour; stored in secure HttpOnly cookie.  
- Region select options from `packages/shared-types/regions.ts`.  
- Duplicate email registration returns HTTP 409.
- Password must include at least **one uppercase letter** and **one numeral**; backend returns HTTP 422 on weak password.
- Email must match RFC 5322 basic format; invalid email returns HTTP 422.
- Email confirmation workflow is out-of-scope and deferred to a later story.

## Dev Agent Record

### Implementation Notes
- **Validation status codes (deviation, agreed with PO):** weak passwords and invalid emails return **400**, like every other validation error in the API, not 422 as written in Technical Constraints. Duplicate email returns 409.
- **Registration rules:** name ≤ 255; email must include a domain dot (the default `@Email` accepts `jane@localhost`); password 8–72 characters with an uppercase letter and a number (72 is BCrypt's limit; longer passwords previously caused a 500); region must be a valid region code.
- **Emails are case-insensitive:** stored lower-cased at registration and lower-cased at login (and for the seeded admin), so `Jane@Example.com` and `jane@example.com` are one account.
- **Sign-up flow:** `/signup` → Next.js `POST /api/auth/register` → API; the access token is stored in the same HttpOnly cookie as login, so the buyer is signed in immediately and lands on `/buyer/profile` (or a safe `?next=`).
- **Profile:** `GET/PUT /buyer/profile`. PUT now replaces the editable fields (full name, region, delivery address); a null address removes it. Email is shown read-only (it is the login identifier). Delivery address is optional, but street and town are required once any part is entered; GPS address is optional, validated as `AK-484-9321` and upper-cased.
- **Routing:** `/login` is now a shared sign-in page for admins and buyers, linking to `/signup`. Middleware: signed-out visitors to `/buyer/**` go to `/signup?next=…` (per the task) and to `/admin/**` go to `/login`; a signed-in user in the wrong area is sent to their own home; signed-in users visiting `/login` or `/signup` go to their home.
- **Refactors:** shared `startSessionVia` for the login/register API routes, `lib/pageSession.ts` (admin + buyer guards), `lib/roles.ts`, shared `Field`/`FormError`/`SignOutButton` components. Home page links to sign-up and sign-in.
- **Fixed:** `BuyerControllerTest` (previously failed to load its context).
- API client functions live in `services/authService.ts` (`register`) and `services/buyerService.ts` rather than `lib/api/*`, matching the existing service layer.
