## Story
**As a** System Admin,
**I want** to create new farmer accounts via a form in the admin dashboard,
**so that** new farmers can be officially registered on the platform.

## Acceptance Criteria
1. An authenticated admin can access a "Create Farmer" page from their dashboard.
2. The form captures the farmer's full name, home region (selected from a predefined list), and contact information.
3. Upon form submission, a new farmer record is created and persisted in the database.
4. A success message is displayed to the admin after the farmer is created.
5. The form includes validation to ensure all required fields are filled correctly.

## Dev Agent Record

### Implementation Notes
- **Regions:** canonical list of Ghana's 16 regions in `packages/shared-types/src/regions.ts` (codes like `GREATER_ACCRA`) mirrored by `Region.java`; `regions.test.ts` fails if they drift. `@ValidRegion` rejects unknown codes with 400. Other DTOs that take a region (buyer registration, pickup locations) are not yet validated.
- **Phone numbers:** accepted as `0XXXXXXXXX` or `+233XXXXXXXXX` (spaces/dashes allowed), validated by `@GhanaianPhoneNumber`, and stored normalised to E.164 so the same number in different formats is caught as a duplicate (409). Emails are trimmed and lower-cased before the duplicate check.
- **Contact details:** phone number is required; email is optional for farmers (many have none). `users.email` is nullable but still unique; admins and buyers, who log in by email, still always have one. Existing local databases need recreating (`docker compose down -v`) to pick up the nullable column.
- **Password (Technical Constraints):** farmers get a random, hashed temporary password (existing behaviour); they cannot log in yet.
- **API access from the browser:** `pages/api/v1/[...path].ts` proxies to the backend and attaches the HttpOnly session token as a Bearer header; components call it through `services/apiClient.ts` → `services/farmerService.ts` (used instead of the `lib/api/admin.ts` path in File Locations, to match the existing `services/` layer). A 401 clears the session and redirects to `/login`.
- **Form:** React Hook Form + Zod (`lib/validation/farmer.ts`), native select styled as shadcn/ui, success toast via `sonner` (shadcn/ui's current toast).
- **Farmers list:** a minimal `/admin/farmers` page (newest 20) exists so the create flow can redirect to it; pagination controls remain for Story 1.4.
- **Also fixed:** `InvalidRequestException` now returns 422 with its message (it was caught by the generic handler and returned 500 everywhere it is used). Create returns `createdAt` (now flushed before mapping). `FarmerControllerTest`/`FarmerServiceTest` repaired. Web `tsconfig` now uses `strict: true`.
- Audit logging of farmer creation is deferred (future story, per Technical Constraints).
