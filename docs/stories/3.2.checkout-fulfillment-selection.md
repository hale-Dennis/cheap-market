## Story
**As a** Buyer,
**I want** to proceed from my cart to a checkout process where I can confirm my order and choose my fulfillment method,
**so that** I can finalize my purchase.

## Acceptance Criteria
1. A "Proceed to Checkout" button in the cart leads to an order summary page.
2. The user must select one of two fulfillment options: "Pickup Point" or "Home Delivery".
3. If "Home Delivery" is selected, the user's address from their profile is used, and the calculated delivery fee is added to the order total.
4. If "Pickup Point" is selected, the user can choose from a list of available pickup locations within their region.

## Dev Agent Record

### Implementation Notes
- **Delivery fee:** flat fee per region from config, as the Technical Constraints say (the PRD's "based on distance" is not implemented). `application.delivery.default-fee-cents` (default 1000 = GH₵ 10, env `DELIVERY_DEFAULT_FEE_CENTS`) plus optional `fee-cents-by-region` overrides; unknown regions or negative fees fail start-up. Computed server-side by `DeliveryFeeService`, exposed publicly at `GET /api/v1/delivery-fees?region=` (cacheable 5 min), and **now also used by `OrderService`**, which previously hard-coded GH₵ 10, so the quoted and charged fees can't diverge.
- **Pickup locations:** `GET /pickup-locations?region=` (existed, buyers only) now validates the region, sorts by name and sends `Cache-Control: private, max-age=300` (private because it needs sign-in). Admin create/update now rejects unknown regions.
- **Checkout page `/checkout`** (buyer-only; signed-out visitors go to `/signup` as specified):
  - Order summary (items × quantity, subtotal, delivery/pickup line, total), recalculated as the option changes.
  - Fulfillment radio group: **Home delivery** shows the profile address with a "Change address" link and the fee; disabled (with a link to the profile) when the buyer has no address. **Pickup** is free and lists the pickup points in the buyer's profile region with address and opening hours; disabled with a message when the region has none.
  - Empty carts and carts with unavailable items can't be checked out; the cart page's "Proceed to checkout" is disabled until unavailable items are removed.
- **Validation (deviation):** the task says to disable "Continue" until a valid option is selected, but the constraints also require a toast when submitting without one. The button stays enabled and submitting without a valid choice shows a **toast plus an inline error** at the choice (more accessible than an unexplained disabled button).
- **Placing the order is Story 3.3:** the "Place order" button validates the selection and currently confirms it with a message; 3.3 wires it to `POST /orders`. Known gaps in the existing `OrderService` for 3.3: it doesn't exclude unavailable items, uses the cart's stored price, doesn't check the pickup point's region, and doesn't require a delivery address.
- API client functions live in `services/checkoutService.ts` rather than `lib/api/public.ts`, matching the existing service layer.
